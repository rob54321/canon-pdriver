1. 簡介
「Linux 專用 Canon UFR II/UFRII LT 印表機驅動程式」為 Linux 作業系統印表機驅動程式，可支援 Canon 裝置，並使用適合 Linux 作業系統的 CUPS (Common UNIX Printing System) 。安裝此驅動程式後，即可使用 GUI (Graphical User Interface) 設定畫面和指令行的內建功能進行列印。

4. 安裝印表機驅動程式
確認電腦連線到網際網路環境後，再安裝驅動程式。
如需驅動程式安裝方法和使用方法的詳細資料，請參閱使用者指南。(→ UFR II/UFRII LT 印表機驅動程式 使用者指南)

使用時的注意事項
1. 安裝時的限制 (適用於所有發佈版本)
如果解除安裝驅動程式套件時用於列印的快取檔案仍保留於「cngplp2」，由於「cngplp2」不會被刪除，因此將會顯示警告。不需要刪除快取檔案。如果想將其刪除，請手動刪除「cngplp2」。
如果以 USB 連線使用印表機，將多台印表機連線到一台電腦，並登錄列印佇列，您可能無法正確列印或取得資訊。如果一台電腦僅連接一台印表機，即可避免這種現象。
如果使用 iR C1021/C1021i、MF8400 系列、MF9100 系列或 MF9300 系列，雖然可以從印表機的控制台設定 IPv6，但是只有 IPv4 支援網路連線。
如果使用隨插即用功能自動登錄透過 USB 連線的印表機，將會登錄使用單向列印連線的印表機，且列印時可能會發生顏色錯誤等問題。必須使用 Printer Setup Utility 或以下命令來登錄需雙向列印連線的裝置。
# /usr/sbin/lpadmin -p [欲登錄的印表機名稱] -P [PPD 檔案路徑] -v cnusbufr2:/dev/usb/lp0 -E
在某些使用的發佈版本中，當您使用列印多工緩衝處理器登錄 USB 印表機時，如果指定「/dev/usb/lp*」作為裝置 URI，列印可能會失敗，並顯示「印表機未連接」的錯誤。若要解決這個問題，請使用下列指令，指定印表機的特定名稱作為顯示的裝置 URI。
範例：使用 MF4600 系列時
(1) 顯示裝置 URI
# /usr/sbin/lpinfo -v
direct usb://Canon/MF4600%20Series%20(FAX)
direct usb://Canon/MF4600%20Series%20(PCL5e)
direct usb://Canon/MF4600%20Series%20(PCL6)
direct usb://Canon/MF4600%20Series%20(UFRII%20LT)
(2) 登錄印表機
# /usr/sbin/lpadmin -p MF4600_USB -P /usr/share/cups/model/CNRCUPSMF4600ZK.ppd -v usb://Canon/MF4600%20Series%20(UFRII%20LT) -E
如果使用 LIPSLX, UFR II/UFRII LT (US) 和 UFR II/UFRII LT (TC) 驅動程式安裝套件安裝超過兩個驅動程式，而只更新其中一個驅動程式，則會發生錯誤。這個問題可透過一併更新所有安裝的驅動程式解決。
端視您的環境而定，Canon Printer Setup Utility 中可能會顯示遠端印表機。也可能無法刪除顯示的遠端印表機。
如果使用 Canon Printer Setup Utility 登錄透過 USB 連線的印表機，儘管印表機需要雙向列印連線，仍可能會登錄使用單向列印連線的印表機。在此情況下，請重新連接 USB 纜線，然後使用 Canon Printer Setup Utility 再次登錄印表機。
如果透過 USB 連接印表機，則登錄印表機時可能不會顯示裝置 URI。
在這種情況下，請使用裝置的控制面板或遠端使用者介面在裝置設定中停用 [使用無驅動程式列印]、[使用AirPrint] 和 [使用Mopria] 中的任意一項。
如果在電腦中沒有安裝運作驅動程式所需的資料庫，只要電腦連線到網際網路，便會自動下載所需的資料庫。如果電腦未連線到網際網路，將取消驅動程式安裝程序。
端視您的環境而定，如果您按兩下安裝套件來安裝驅動程式，可能不會正確執行安裝。在此情況下，請使用安裝程式來安裝驅動程式。
2. 安裝時的限制 (發佈版本限定)
在 Fedora 中
在安裝驅動程式、升級驅動程式或執行安裝程式時，雖然可能會出現警告，表示不鼓勵使用 yum 指令，但是安裝仍然會正確執行，不會發生問題。
在 Debian 中
可能因為無法成功下載必要的資料庫，而無法安裝驅動程式。如果發生此情形，請依下列說明以超級使用者權限編輯並儲存用於作業系統套件的下載目的地清單 (/etc/apt/sources.list)。
將以下鏡射重新導向器服務 URL 新增為下載目的地：
deb http://httpredir.debian.org/debian [作業系統版本代號] main
範例 (Debian 9.0)：deb http://httpredir.debian.org/debian stretch main
將「#」新增至以下「deb cdrom: ...」程式碼行的開頭，指定 CD/DVD 作為下載目的地以取消規格：
# deb cdrom: ...
3. 列印時的限制 (適用於所有發佈版本)
端視您的環境而定，可能無法使用管理員權限啟動應用程式。在此情況下，請執行下列指令啟動應用程式。
$ xhost +SI:localuser:root
依照 CUPS 規格，進行列印時，列印佇列中可以容納的最大檔案數量為 500。在第 500 個檔案後加入佇列的檔案，都會被忽略。
在 [一般] 頁中為 [頁面佈局] 指定多個頁面/份數，以列印使用StarSuite7/OpenOffice建立的文件時，由於 CUPS 模組的作業原因，設定不會正確指派到多個頁面和輸出。
使用 OpenOffice.org 或 StarSuite 中指定的份數建立的 PostScript 檔案，不會受到 [cngplp2] 畫面 (驅動程式使用者介面) 中 [份數] 指定的值影響，而是受到建立 PostScript 檔案時設定的份數影響。
如果在如 OpenOffice.org 的 Writer 等應用程式的列印畫面中指定紙張來源設定，來自應用程式的設定會被印表機驅動程式使用者介面的設定覆寫。為了從所需的紙張來源進行列印，請事先從印表機驅動程式使用者介面中指定紙張來源，或是從指令行進行列印。
如果您是從驅動程式使用者介面或指令行列印 TIFF 或 JPEG 影像，影像可能會被分割，而列印到跨越數個頁面上。若要解決這個問題，可以將影像從 GIMP 等應用程式輸出為 PostScript 檔案，然後從驅動程式使用者介面或指令行列印 PostScript 檔案。
在設定項目和文字檢視值之後，如果您按下對話方塊右上角的 [X] 按鈕完成設定，此值會被視為有效值，就如同按下 [確定] 按鈕一樣。如果要停用設定的值，請按下 [取消] 按鈕。
如果您在列印時指定了超過 32 位元組的文件名稱，驅動程式會刪除第 33 個位元組以後的文件名稱字元字串，且裝置中顯示的文件名稱最大為 32 個位元組。
如果從 [cngplp2] 畫面或指令行列印 PDF 影像檔案，某些影像的列印結果可能會出現黑色色塊。
如果您在可以使用 Adobe Reader 9的環境中，列印時可以在 [進階列印設定] 對話方塊中，選擇 [讓印表機決定色彩] 或 [以影像方式列印] 以解決這個問題。
使用 Adobe Reader 8 列印 PDF 檔案時，有些影像可能不會列印出來。可透過使用 Adobe Reader 7 或 9，或是在 PostScript 選項中設定等級 3 解決這個問題。
某些 CUPS 版本中，可能無法正確列印用於 lpoptions 的「#」或「\」。請勿使用這些字元。
如果您使用 CUPS 1.6.3 版或更舊版本，透過 USB 連接電腦和裝置使印表機自動登錄時，第二次之後資料可能無法正確列印。使用 Canon Printer Setup Utility 再次登錄印表機，即可避免此問題。
如果從驅動程式使用者介面變更設定，則在列印處理期間，列印的結果會反映變更後的設定。
如果未正確設定 [部門 ID 管理認證]/[機密列印認證]，可能無法使用驗證功能或執行列印。如果裝置支援驗證資訊加密功能，請設定 [模式 2]。否則，請設定 [模式 1]。
在OpenOffice.org中進行列印時，某些完稿功能如 [旋轉]，可能無法在驅動程式使用者介面中將 [份數] 指定為多份的情況下正確運作。
如果安裝了 [Finisher-Q3] 或 [Saddle Finisher-Q4]，而您指定 A4、Letter 或 Legal 作為頁面大小，則在 [完稿] 頁中將 [裝訂位置] 設定為 [短邊 (頂端)]，且 [裝訂位置] 設定為 [正上方 (雙針)]，或將 [裝訂位置] 設定為 [短邊 (底邊)]，且 [裝訂位置] 設定為 [底邊 (雙針)] 時嘗試列印，文件將無法正確列印。
如果從 [cngplp2] 畫面或指令行列印 TIFF 影像檔案，某些影像的列印結果可能會出現黑色色塊。使用以下其中一種方法即可避免此問題。
(1) 從 GIMP 等應用程式進行列印。
(2) 將檔案輸出為 PostScript 檔案，然後從 [cngplp2] 畫面列印輸出的 PostScript 檔案。
如果您在指定 [機密列印] 作為輸出方式之後，將輸出方式改為 [列印]，然後按下驅動程式使用者介面中的 [儲存設定]，則您使用 [機密列印] 輸出的文件名稱，會顯示在印表機的工作日誌中。如欲解決這個問題，可以在輸出方式從 [機密列印] 變更為 [列印] 時，使用 [儲存設定] 按鈕取代 [列印] 按鈕進行列印。
依 GTK (GIMP Toolkit) 的版本，某些字元顯示在螢幕上時可能不可懂，但是這並不表示功能和值的設定出現問題。重繪對應的文字區域可以解決這個問題。
如果您透過從桌面或命令行直接指定檔案的方式列印 PDF 文件，可能無法正確列印文件。列印 PDF 文件時，建議從 Acrobat Reader 或 Adobe Reader 列印。
如果您使用 Adobe Reader 7.0.x 並在列印畫面中修改紙張大小、紙張來源或雙面列印等設定，這些選項會自動加入印表機命令中。
但是，這些設定不會發揮作用，因為無法辨識出它們是命令選項。如欲解決這個問題，請使用 -o 分隔每個命令選項。
[變更前]
-o InputSlot=Manual,Duplex=DuplexNotumble
[變更後]
-o InputSlot=Manual -o Duplex=DuplexNoTumble
使用 Adobe Reader 8.1.2 執行雙面列印時，如果在 Adobe Reader 8.1.2 的列印屬性中，將 [雙面列印] 指定為 [開 (短邊裝訂)]，文件會列印為雙面和長邊裝訂。使用印表機驅動程式使用者介面列印文件，即可避免此問題。
MF4270 或 L90/L160/L230 印表機在某些環境和列印資料類型中，可能會因為裝置端的印表機資料錯誤而無法列印。這是裝置端發生的逾時錯誤所造成的。這個問題可以透過關閉裝置的錯誤逾時設定而避免。
列印橫幅頁時，可列印指定份數的橫幅頁。
亮度和 Gamma 校正設定可能不會反映在列印結果中。
當您透過 USB 連線使用裝置時，如果試圖連續列印相同的資料，第二次之後資料可能無法正確列印。這是裝置和作業系統之間資料傳輸時發生不一致所造成的。
這個問題可透過拔掉 USB 纜線並重設 USB 連接埠之後，新增下列選項而獲得解決。
# /usr/sbin/lpadmin -p [登錄的印表機名稱] -o usb-no-reattach-default=true
如果您使用 1.5 版或更早版本的 CUPS，這個問題可透過拔掉 USB 纜線並重設 USB 連接埠之後，依下列方式指定 cnusbufr2 而獲得解決。
# /usr/sbin/lpadmin -p [登錄的印表機名稱] -P [PPD 檔案路徑] -v cnusbufr2:/dev/usb/lp0 -E
使用 CUPS 版本 2.2.12/2.3.0 時，即使您在 [cngplp2] 畫面上按下 [設定為預設值]，也可能無法將 [名稱] 中選擇的印表機設為預設印表機。如果按一下 [儲存設定]，還可能會變更預設印表機。
使用 Debian 類型作業系統時，只能建立和執行 Canon UFR II/UFRII LT Printer Setting Utility 的捷徑。
如果登錄印表機，只能執行 Canon UFR II/UFRII LT Printer Setting Utility 的捷徑。
只能透過執行 Canon UFR II/UFRII LT Printer Setting Utility 的捷徑來變更預設設定。無法執行列印。
如果您在應用程式中對於 [紙張尺寸] 和 [列印區域] (這兩項都可以選擇) 選擇不同的尺寸，則用於輸出的尺寸將取決於您使用的應用程式。
從應用程式列印時，端視您的環境而定，畫面上顯示的驅動程式功能和設定名稱可能不正確。
由於此驅動程式適用於全部國家和地區，因此可能允許您選擇印表機不支援的紙張尺寸或紙張類型。如果選擇不支援的紙張尺寸或紙張類型，印表機可能會出現錯誤，因為無法列印。
4. 列印時的限制 (發佈版本限定)
在 Fedora/Ubuntu/Debian/UOS/Kylin OS/NeoKylin OS 中
如果您要列印到支援驗證資訊加密功能的裝置，則兩方都需要 beecrypt 資料庫。
beecrypt 資料庫安裝指令的範例如下。
<Fedora>
# dnf install beecrypt beecrypt-devel
<Ubuntu14.04 到 15.10/Debian8>
# apt-get install libbeecrypt7 libbeecrypt-dev
<Ubuntu16.04 及更新版本/Debian9 及更新版本/UOS/Kylin OS>
# apt-get install libgcrypt20 libgcrypt20-dev
<NeoKylin OS>
# yum install libgcrypt libgcrypt-devel
如果使用彩色印表機，視印表機型號而定，在沒有安裝 JPEG 資料庫 (libjpeg62) 的情況下可能會無法列印。
如果發生此狀況，請執行下列指令安裝資料庫後再列印。
<Fedora>
# dnf install libjpeg-turbo
<Ubuntu/Debian/UOS/Kylin OS>
# apt-get install libjpeg62
<NeoKylin OS>
# yum install libjpeg-turbo
如果使用黑白印表機，視印表機型號而定，在沒有安裝 JBIG-KIT 資料庫的情況下可能會無法列印。
如果發生此狀況，請執行下列指令安裝資料庫後再列印。
<Fedora>
# dnf install jbigkit-libs
<Ubuntu/Debian/UOS/Kylin OS>
# apt-get install libjbig0
<NeoKylin OS>
# yum install jbigkit-libs
在 Fedora/NeoKylin OS 中
列印包含多位元組字元的字元字串時，相關區域中列印出的字元之間的空間可能會縮小。這個問題可以藉由在其他文字編輯器中列印而解決，例如 gedit。
當您嘗試從 [cngplp2] 畫面或指令行中列印 4 位元組 UTF-8 字元時，字元可能不會印出。另外，在使用 gedit、Firefox 等應用程式列印這些字元時，字元可能難以辨識。這些問題是由系統造成。
在 Ubuntu/UOS/Kylin OS 中
從 [cngplp2] 畫面或指令行列印包含多位元組字元代碼的文字資料時，列印結果可能包含亂碼字元或列印可能失敗。如果發生這種狀況，可以透過從 gedit 之類的文字編輯器中列印來解決此問題。
在 UOS 中
當使用 cngplp2 指令列印工作時，可能會因為沒有安裝 lpr 公用程式而發生 I/O 錯誤。
在此情況下，請執行下列指令安裝公用程式後再列印。
# apt-get install cups-bsd
列印工作時，可能會因為沒有安裝 CUPS 影像篩選程式資料庫而發生篩選器錯誤。
在此情況下，請執行下列指令安裝資料庫後再列印。
# apt-get install libcupsimage2
